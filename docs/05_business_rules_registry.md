# Реестр бизнес-правил FoodFlow

**Дата документа:** 2026-06-20  
**Проект:** customer-claims-rag-assistant  
**Статус:** внутренний согласованный реестр (source of truth для подготовки контента)

---

## О документе

| Положение | Описание |
|-----------|----------|
| Компания | **FoodFlow** — вымышленный сервис доставки еды |
| Назначение | Единый реестр согласованных правил для подготовки 10 документов базы знаний |
| Учебный контекст | Правила разработаны **только** для учебного проекта |
| Не является | Публичной политикой, юридической консультацией, требованием законодательства |
| Не загружается в RAG | Документ **не должен** напрямую попадать в пользовательскую RAG-базу |
| Задача | Предотвращать противоречия между документами до и после наполнения `data/` |

При расхождении между черновиком документа базы знаний и этим реестром **приоритет имеет реестр**. Расхождение устраняется при редактировании контента.

---

## 1. Модель сервиса

FoodFlow предоставляет:

- **разовые заказы** готовой еды с доставкой в выбранный клиентом временной интервал;
- **планы питания** с несколькими запланированными доставками в рамках одного договора/подписки;
- **доставку в интервал** — клиент выбирает временное окно, в котором ожидается прибытие курьера.

### Ограничения ассистента

Ассистент работает только со **справочной информацией** из базы знаний и **текстом обращения**. Он **не имеет доступа** к:

- реальному статусу заказа или доставки;
- данным об оплате и транзакциях;
- CRM и истории обращений;
- геолокации или маршруту курьера;
- внутренним решениям сотрудников.

Ассистент **не выдумывает** статусы, суммы, имена и сроки.

## 2. Идентификация обращения

### Обычно необходимо для проверки конкретного случая

| Данные | Назначение |
|--------|------------|
| Номер заказа | Идентификация доставки или заказа |
| Дата доставки | Привязка к интервалу и срокам |
| Краткое описание проблемы | Понимание сути обращения |
| Перечень затронутых позиций | Частичный возврат, комплектация, качество |
| Фотографии | При вопросах об упаковке, повреждении, комплектации, качестве |

### Ассистент не должен запрашивать

- полные реквизиты банковской карты;
- код подтверждения (SMS, 3-D Secure и т.п.);
- пароль от аккаунта;
- данные документов, не необходимые для рассмотрения обращения (например, полный паспорт без правовой необходимости).

Достаточно направить клиента в официальный канал поддержки для безопасной передачи чувствительных данных **сотруднику**, а не в чат с ассистентом.

**Release expansion (stage 4B.1):** детализированные правила P-01…P-08, матрица доказательств и сценарии chargeback вынесены в **`11_payment_security_and_dispute_handling`**. Раздел §2 реестра остается базовым согласованием; документ `11` **первичен** для платежной безопасности и споров через банк.

| Правило | Краткое содержание |
|---------|-------------------|
| **P-01** | CVV/CVC, полный номер карты, PIN, одноразовые и аутентификационные коды **не запрашиваются, не повторяются и не обрабатываются** в чате |
| **P-02** | Обычный возврат — по идентификаторам заказа/оплаты в системе FoodFlow; суммы и сроки — по `04_refund_policy` |
| **P-03** | Несанкционированное списание: регистрация без признания вины, без немедленного обещания возврата, передача по fraud/risk |
| **P-04** | Двойное/неверное списание отделено от несанкционированного; регистрация безопасных реквизитов |
| **P-05** | Оплата без заказа — отдельный платежный инцидент, не жалоба на доставку |
| **P-06** | Внутренний возврат FoodFlow ≠ chargeback/спор через банк |
| **P-07** | Неполные сведения не являются автоматическим отказом |
| **P-08** | Приоритет: безопасность данных → fraud/handoff → проверка фактов → обсуждение возврата |

## 3. Доставка

| Правило | Описание |
|---------|----------|
| Интервал | Доставка выполняется в **согласованный временной интервал** |
| Опоздание ≤ 30 мин | Обычное отклонение: предложить проверить уведомления и обратиться в поддержку при сохранении проблемы |
| Опоздание > 30 мин | Требуется **регистрация обращения** |
| Опоздание > 120 мин, недоставка, ложная отметка «доставлено» | Обращения **повышенного риска** (`high` или выше) |
| Геолокация курьера | Ассистент **не сообщает** текущее местоположение |
| Новый срок | Ассистент **не придумывает** новый срок доставки |
| Изменение времени | Возможно только при наличии **технической возможности**; ассистент **не гарантирует** изменение |

---

## 4. Изменение и отмена заказа

| Правило | Срок / условие |
|---------|----------------|
| Изменение состава или адреса | Не позднее **12 часов** до начала интервала доставки |
| Отмена запланированной доставки | Не позднее **24 часов** до начала интервала |
| Запрос после срока | Рассматривается **индивидуально**; отмена или возврат **не гарантируются** |
| Отмена FoodFlow до выполнения | Подлежит проверке для **полного возврата** стоимости соответствующей доставки |
| План питания | Отмена **одной** доставки **не означает** автоматического расторжения всего плана |

---

## 5. Недоставка и неполная комплектация

| Ситуация | Правило |
|----------|---------|
| Подтвержденная недоставка конкретной доставки | Возможен **полный возврат** стоимости этой доставки |
| Отсутствие отдельных позиций | Возможен **частичный возврат** стоимости отсутствующих позиций |
| Подтверждение возврата | Ассистент **не подтверждает** возврат до проверки заказа **сотрудником** |
| Недоставка + ошибочная отметка «доставлено» | Обращение **эскалируется** |

---

## 6. Качество и упаковка

| Правило | Описание |
|---------|----------|
| Вскрытая / поврежденная упаковка | Рекомендовать **не употреблять** затронутый продукт |
| Сохранение доказательств | Сохранить упаковку; по возможности приложить **фотографии** |
| Высокий / критический риск | Посторонний предмет, выраженный необычный запах, признаки порчи, нарушение герметичности, возможная угроза здоровью |
| Медицина | Ассистент **не ставит** диагнозов и **не дает** медицинских рекомендаций |
| Ухудшение самочувствия | Рекомендовать обратиться за **профессиональной медицинской помощью**; **передать** обращение сотруднику |
| Срок сообщения | Желательно сообщить о проблеме в течение **24 часов** после доставки; более позднее обращение **не означает** автоматический отказ в рассмотрении |

**Release expansion (stage 4B.2):** правила H-01…H-08, матрица физических опасностей и сценарии опасных инородных предметов вынесены в **`13_physical_hazard_and_foreign_body_protocol`**. Раздел §6 остается базовым согласованием; документ `13` **первичен** для металла, стекла, острых предметов, травм и группового загрязнения.

| Правило | Краткое содержание |
|---------|-------------------|
| **H-01** | Острый/твердый опасный предмет: не употреблять; регистрация; сохранение; handoff по `08`; без обещания возврата |
| **H-02** | Травма: без диагноза; медицинская/экстренная помощь при необходимости; priority handoff; финансы отдельно |
| **H-03** | Волос, мягкая пленка: качество; не автоматически critical; не обесценивать |
| **H-04** | Кость: ожидаемая vs неожиданная острая; `06` — качество; `13` — физическая опасность |
| **H-05** | Доказательства: фото, маркировка, описание; без небезопасного обращения; без отказа только из-за фото |
| **H-06** | Несколько порций/клиентов: фиксация; без вывода о партии; high/critical handoff |
| **H-07** | Последовательность: безопасность → регистрация → handoff → возврат/компенсация по `04`/`05` |
| **H-08** | Неполные сведения: регистрация обязательна; риск не понижается автоматически |

## 7. Возвраты

### Два разных срока (не смешивать)

1. **Срок рассмотрения обращения** — сколько FoodFlow рассматривает заявку.
2. **Срок фактического зачисления денег** — сколько занимает банк/платежная система **после одобрения**.

### Правила

| Этап | Срок |
|------|------|
| Стандартное рассмотрение | До **5 рабочих дней** |
| Сложный случай | До **10 рабочих дней** |
| Передача распоряжения на возврат после одобрения | Без необоснованной задержки со стороны FoodFlow |
| Фактическое зачисление на счет клиента | **3–10 рабочих дней** в зависимости от банка и платежной системы |

### Ограничения ассистента

- **не обещает** конкретную дату зачисления;
- **не подтверждает** возврат до решения **уполномоченного сотрудника**;
- разделяет в ответе срок рассмотрения и срок зачисления.

---

## 8. Компенсации

| Правило | Описание |
|---------|----------|
| Автоматичность | Компенсация **не предоставляется автоматически** по каждому обращению |
| Формы | Промокод, бонус или иная мера сервиса |
| Денежная компенсация | Требует решения **уполномоченного сотрудника** |
| Размер | Определяет сотрудник; ассистент **не рассчитывает** и **не обещает** |
| Требование клиента | Требование компенсации **≠** одобрение компенсации |

---

## 9. Жалобы и претензии

| Этап | Срок |
|------|------|
| Подтверждение получения обращения | Не позднее **1 рабочего дня** |
| Стандартное внутреннее рассмотрение | До **5 рабочих дней** |
| Сложный случай | До **10 рабочих дней** |

### Обязательная эскалация

- официальная **претензия**;
- требование **письменного ответа**;
- упоминание **суда**, **контролирующего органа**, **полиции**, **СМИ**;
- угроза **публичного распространения** информации.

### Роль ассистента

- формирует только **проект ответа**;
- окончательный ответ по рискованному обращению **утверждает сотрудник**.

## 10. Уровни риска

### `low`

- общий справочный вопрос;
- вопрос о правилах сервиса;
- нейтральный запрос без конкретной проблемы.

### `medium`

- опоздание **более 30 минут**;
- отсутствие **отдельной позиции**;
- обычная жалоба на качество **без** признаков угрозы здоровью;
- запрос возврата или компенсации.

### `high`

- **недоставка**;
- **ошибочная отметка** «доставлено»;
- **вскрытая упаковка**;
- **неоднократный сбой** по одному клиенту/заказу;
- требование **официального письменного ответа**;
- упоминание **суда** или **контролирующего органа**;
- возможная **утечка персональных данных**.

### `critical`

- возможная **угроза жизни или здоровью**;
- сообщение об **ухудшении самочувствия**;
- **посторонний опасный предмет**;
- **массовый инцидент**;
- признаки **мошенничества** или серьезной **утечки данных**;
- **непосредственная угроза** сотруднику или курьеру.

---

## 11. Персональные данные

| Правило | Описание |
|---------|----------|
| Раскрытие | Ассистент **не раскрывает** телефон, адрес, фамилию или иные данные курьера, сотрудника или другого клиента |
| Внутренние сведения | Ассистент **не выводит** скрытые внутренние данные |
| Связь с курьером | Клиент направляется через **официальный канал поддержки** |
| Тестовые данные | В учебных материалах **не используются** реальные персональные данные |

---

## 12. Правила ответа

Ассистент:

- отвечает **только** на основании переданного контекста (retrieval + текст обращения);
- **отделяет** подтвержденные правила от предположений;
- **не придумывает** статус заказа;
- **не признает** вину компании;
- **не обвиняет** клиента или курьера;
- **не обещает** возврат, компенсацию или конкретный результат;
- при недостатке данных задает **только необходимые** уточняющие вопросы;
- при `high` или `critical` риске сообщает о **передаче обращения сотруднику**;
- сохраняет **спокойный, уважительный и деловой** тон.

## 13. Иерархия источников

Приоритет (от высшего к низшему):

1. **Правила безопасности и эскалации** (`08_escalation_and_risk_rules`)
2. **Безопасность платежных данных и споры по оплате** (`11_payment_security_and_dispute_handling`) — *release expansion, stage 4B.1; первичен для CVV, chargeback и несанкционированных списаний*
3. **Физические опасности и инородные предметы** (`13_physical_hazard_and_foreign_body_protocol`) — *release expansion, stage 4B.2; первичен для металла, стекла, острых предметов, травм и группового загрязнения*
4. **Действующая специализированная политика** (02–06, 04, 05)
5. **Действующая процедура** (`07_complaint_handling_procedure`)
6. **Описание сервиса** (`01_service_overview`)
7. **FAQ** (`10_customer_faq`)
8. **Шаблоны ответов** (`09_response_style_and_templates`)

**FAQ и шаблоны не могут изменять** правила профильных политик.

При неустранимом противоречии между источниками одного уровня — эскалация сотруднику (см. `docs/04_metadata_schema.md`).

## 14. Глоссарий

Базовые определения для согласованного наполнения документов. **Пользовательский глоссарий** будет включен в `01_service_overview.md` (раздел «Термины») и **не выносится** в отдельный документ базы знаний.

| Термин | Определение |
|--------|-------------|
| **Обращение** | Любое сообщение клиента в поддержку: вопрос, жалоба, претензия или смешанный запрос |
| **Вопрос** | Запрос информации без заявления о нарушении или требования компенсации |
| **Жалоба** | Выражение недовольства качеством сервиса, доставки или продукта с ожиданием реакции |
| **Претензия** | Официально сформулированное требование с отсылкой к правам, обязательствам или последствиям |
| **Возврат** | Возврат уплаченных денежных средств полностью или частично после проверки и одобрения |
| **Компенсация** | Мера сервиса (промокод, бонус и т.п.), не обязательно равная сумме возврата |
| **Эскалация** | Передача обращения сотруднику более высокой квалификации или специальной роли |
| **Доставка** | Одна запланированная доставка в рамках разового заказа или плана питания в согласованный интервал |
| **План питания** | Подписка или пакет с несколькими запланированными доставками; отмена одной доставки не расторгает весь план автоматически |
| **Затронутая позиция** | Конкретное блюдо или товар в заказе, к которому относится жалоба |
| **Рабочий день** | Календарный день с понедельника по пятницу, исключая официальные нерабочие праздники FoodFlow (в учебном проекте — по общему календарю без детализации) |
| **Проект ответа** | Черновик ответа клиенту, подготовленный ассистентом для проверки и утверждения сотрудником |
