**Дата документа:** 2026-06-20  
**Проект:** customer-claims-rag-assistant  
**Этап:** первая партия документов (01–03), второй цикл после независимого аудита

---

## 1. Цель очистки

Сырые материалы в `data/01_raw/` имитируют фрагменты, полученные от условного заказчика: с колонтитулами, дублями и устаревшими блоками. Очистка преобразует их в структурированный Markdown в `data/02_clean_markdown/` для:

- индексации и чанкинга по `docs/03_chunking_strategy.md`;
- добавления YAML-метаданных по `docs/04_metadata_schema.md`;
- согласования содержания с `docs/05_business_rules_registry.md`;
- использования в RAG-базе знаний MVP.

---

## 2. Примененные операции

| Операция | Описание |
|----------|----------|
| Удаление колонтитулов | Убраны повторяющиеся блоки `FOODFLOW \| ...` |
| Удаление номеров страниц | Убраны пометки `стр. N` |
| Удаление оглавлений | Черновые TOC не переносились в clean |
| Удаление комментариев редактора | Убраны `[РЕДАКТОР: ...]`, `[СЛУЖЕБНО: ...]`, `[KPI ...]` |
| Удаление устаревших фрагментов | Блоки `УСТАРЕЛО` / `АРХИВ` с порогами 90 мин и 8 ч исключены |
| Устранение дублей | Повторяющиеся абзацы и дублирующие таблицы порогов объединены |
| Нормализация пробелов | Лишние пустые строки сокращены |
| Структура заголовков | 10–14 самодостаточных H2 вместо микросекций |
| Списки и таблицы | Маркированные списки и таблицы Markdown |
| Терминология | Унификация: «12 часов», «24 часа», «30/120 минут», «повышенный риск» |
| Метаданные YAML | Front matter с каноническими `document_id`, `category`, `version: 1.0.0` |
| Проверка по реестру | Сверка сроков, рисков, ограничений ассистента |

## 4. Примеры «до и после»

### 01_service_overview

**До (фрагмент raw):**
```text
--- УСТАРЕЛО / АРХИВ (не использовать) ---
Ранее ассистенту разрешалось сообщать «примерное время прибытия курьера»
на основании внутренней карты. С 2026-06-01 это запрещено.
```

**После (clean):**
```markdown
AI-ассистент **не** сообщает местоположение или маршрут курьера.
```

### 02_delivery_rules

**До (фрагмент raw):**
```text
--- УСТАРЕЛО (не применять с 2026-06-01) ---
Существенным опозданием считалась задержка более **90 минут**...
```

**После (clean):**
```markdown
## Каноническое правило интервала и задержки
Опоздание **более 120 минут** относится к обращениям **повышенного риска** (`high`).
```

### 03_order_changes_and_cancellations

**До (ошибочный пример в первой версии clean):**
```markdown
**Удаление десерта за 10 часов.** Запрос в пределах 12 часов...
**Отмена за 23 часа.** В пределах 24 часов.
```

**После (исправлено):**
```markdown
3. Клиент за 10 часов до интервала хочет удалить суп. Запрос **поздний**.
11. Клиент обращается за 23 часа с просьбой отменить доставку. Это **поздний** запрос.
```

**Удалено из clean (не подтверждено реестром):**
```markdown
Возможны частичное удержание или иной исход — только по решению сотрудника.
```
Заменено нейтральной формулировкой: поздний запрос рассматривается индивидуально; финансовый результат определяет уполномоченный сотрудник; ассистент его не определяет.

## Повторная проверка после независимого аудита

**Вердикт аудита:** REVISION REQUIRED (только партия 01–03).

### Обнаруженные ошибки

| Область | Ошибка |
|---------|--------|
| Метаданные | Неверные `document_id` (`service_overview` вместо `01_service_overview`); `category: service_information` / `order_management`; `version: "1.0"`; `confidentiality: public` у политик `02` и `03` |
| Схема | Отсутствовал `internal_reference` в описании `source_type`; не был зафиксирован канонический словарь `category` |
| `03` — сроки | Примеры 10 ч, 8 ч, 23 ч ошибочно названы «в пределах срока» |
| `03` — правило | Формулировка «частичное удержание или иной исход» отсутствует в реестре |
| Структура | Дублирующие заголовки «Дополнительные примеры»; повтор правил 12/24 ч и таблиц 30/120 мин |
| Объем | Raw и clean ниже целевых диапазонов |
| `01` | Микросекции, неполная эскалация, неверный список связанных документов |

### Внесенные исправления

- Обновлен `docs/04_metadata_schema.md`: `internal_reference`, канонический словарь `category`, правила `document_id`, SemVer, `confidentiality`.
- YAML всех трех clean-файлов приведен к согласованным значениям (`1.0.0`, канонические `document_id` и `category`).
- Переписаны clean-файлы 01–03 с расширением содержания и объединением микросекций.
- Raw-файлы дополнены шумным, но согласованным содержанием; сохранены архивные блоки 90 мин / 8 ч только в raw.

### Расширенные разделы

| Документ | Разделы |
|----------|---------|
| `01` | Эскалация (high/critical, все основания реестра), роли (включая уполномоченного сотрудника), каналы и безопасность данных, проект vs финальный ответ, резервное буферное время после интервала, связанные документы 02–10 |
| `02` | Технические обстоятельства, погода/дороги, адрес и доступ, недоступность клиента, частичная доставка, повторяющиеся нарушения, 8+ пограничных сценариев, памятка ассистента |
| `03` | Изменение состава/адреса/интервала, план питания, отмена FoodFlow, 20 пограничных примеров в одном разделе |

### Устранение микросекций и дублей

- `01`: объединены разрозненные блоки про роли, каналы, глоссарий и примеры в 12 H2.
- `02`: канонический раздел «Каноническое правило интервала и задержки» (30/120 мин); сценарные разделы ссылаются на него; удалены повторные «сводные таблицы» и «дополнительные примеры».
- `03`: правило 12/24 ч сформулировано один раз в разделе «Ключевое правило сроков»; 13 H2 и 3 H3; примеры собраны в «Примеры и пограничные ситуации».

### Исправление примеров 10 / 8 / 23 часа

| Пример | Было (ошибка) | Стало |
|--------|---------------|-------|
| Изменение за 10 ч | «в пределах 12 часов» | **поздний** запрос |
| Изменение за 8 ч | «в пределах 12 часов» | **поздний** запрос |
| Отмена за 23 ч | «в пределах 24 часов» | **поздний** запрос |
| Изменение ровно за 12 ч | — | **своевременный** |
| Отмена ровно за 24 ч | — | **своевременная** |

### Синхронизация метаданных

Все три clean-файла соответствуют обновленной схеме. `document_id` совпадает с именем файла; версия `1.0.0`; `01` — `internal_reference` / `public`; `02` и `03` — `internal_policy` / `internal`.
